# IdleNoMore · DeskClock

Turns an old Android phone into an always-on, landscape-first desk display: a big clock,
today's calendar, personal reminders, a photo frame and a custom dashboard.
Built with Expo (SDK 58) and TypeScript. Local-first: no accounts, no backend, no tracking.

## What it does

Swipe left and right between pages (reorder or hide them in Settings › Screens):

| Page | What you see |
| --- | --- |
| **Clock** | Huge clock and date. Layouts: *Agenda* (today's events and reminders beside the clock), *Minimal*, *Photo clock*. |
| **Calendar** | Today's agenda from calendars synced to the phone: now / next / finished, all-day events, refresh, event details, and **Add event** (title, day, time, duration or all-day, calendar, location). |
| **Reminders** | Local reminders with date and time, overdue markers, one-tap complete, edit, delete, notifications. |
| **Photos** | Slideshow of photos you pick with Android's photo picker: interval, pause, fit/fill, clock overlay, crossfade. |
| **Dashboard** | Grid, Feature or Columns arrangement of widgets: clock, date, agenda, reminders, photo, battery, countdown. |

Desk mode keeps the screen on, hides the system bars, and applies a day/night schedule with
separate brightness levels and a near-black night theme (amber or red). Tap the screen for
quick controls; the gear icon opens Settings. Everything you change is saved on the phone.

## Requirements

- Node.js LTS (20 or newer), Watchman
- JDK 17 (Zulu 17) with `JAVA_HOME` pointing at it
- Android Studio with the Android SDK, and `ANDROID_HOME` set
- An Android phone or emulator running Android 7.0 (API 24) or newer

Shell profile (`~/.zshrc`):

```sh
export JAVA_HOME=/Library/Java/JavaVirtualMachines/zulu-17.jdk/Contents/Home
export ANDROID_HOME=$HOME/Library/Android/sdk
export PATH=$JAVA_HOME/bin:$ANDROID_HOME/emulator:$ANDROID_HOME/platform-tools:$PATH
```

## Running

Development (loads code from your Mac, live reload):

```sh
npm install
npm run android        # builds the development app, installs it, starts Metro
```

After the first build `npm start` is enough while you only change TypeScript.
Rebuild with `npm run android` whenever a native package or `app.json` changes.

Standalone (runs without the Mac or a cable):

```sh
cd android && ./gradlew assembleRelease
adb install -r app/build/outputs/apk/release/app-release.apk
```

The release build is signed with the debug key, which is fine for your own phone but not for
the Play Store. `android/` is generated by Expo (Continuous Native Generation) and is not
committed; native settings live in `app.json`.

## Permissions

| Permission | Why | When it's asked |
| --- | --- | --- |
| `READ_CALENDAR` | Show today's events | On the Calendar page, after an explanation. |
| `WRITE_CALENDAR` | Add events from the app | The first time you add an event (Android usually grants it silently once reading is allowed). The app only adds events; it never edits or deletes yours. |
| `POST_NOTIFICATIONS` | Reminder alerts | When you save your first reminder. Reminders still show in the app if denied. |
| `SCHEDULE_EXACT_ALARM` | On-time reminders | Granted automatically on Android 12–13. |

Not requested: storage (the photo picker needs none), camera, microphone, system brightness.

## Limitations (Android, not bugs)

- **Brightness** is app-level: it applies only while DeskClock is on screen.
- **Screen off**: apps can't switch the screen off or on. The sleep schedule only stops holding
  the screen on, so the phone's normal timeout applies; tap it to wake.
- **After a reboot** the app doesn't start by itself; open it again.
- **Battery restrictions**: on MIUI/HyperOS set DeskClock's battery saver to "No restrictions",
  otherwise Android may close it.
- **Reminders** are exact on Android 12–13. Android 14+ denies exact alarms by default, so they
  can arrive a few minutes late there.
- **Calendar** shows what the phone's calendar provider has synced; new Google events can take a
  few minutes to appear.
- **Photos**: Android's picker selects photos and albums, not folders. Picked photos are copied
  (resized to 2048 px) into the app's private storage so they survive restarts.
- **Time-zone changes**: the JavaScript engine keeps the zone it started with, so the app
  restarts itself within a minute of a zone change.
- **Burn-in**: the clock shifts a few pixels every 3 minutes and night mode is near-black; this
  reduces OLED wear but can't prevent it.
- **Debug builds** keep the screen on everywhere (an Expo development feature); release builds
  only keep it on in desk mode.
